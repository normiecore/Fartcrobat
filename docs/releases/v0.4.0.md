## Fartcrobat is now Inkmoor

Same app, new name. Copies of Fartcrobat 0.2 or 0.3 update to Inkmoor like any other update, and keep what you set up:

- **Settings, recent files, Digital IDs and AI app connections carry over.** Inkmoor keeps using the folder Fartcrobat stored them in.
- **Windows:** the update replaces Fartcrobat in place, in the same folder. The Fartcrobat shortcuts are replaced by Inkmoor ones on the desktop and in the Start menu; if you pinned Fartcrobat to the taskbar, pin Inkmoor again. If you made Fartcrobat the default PDF app in Inkmoor's Preferences or the installer, Inkmoor is; if you picked Fartcrobat.exe under "Open with", choose Inkmoor there once more (Preferences offers Make default).
- **Mac:** download Inkmoor below, drag it to Applications, then move Fartcrobat to the Bin.
- **Ubuntu and Debian:** `sudo apt install ./inkmoor_0.4.0_amd64.deb` upgrades the installed Fartcrobat package (it keeps its package name, `fartcrobat`). The app moves to `/opt/Inkmoor` and the command is now `inkmoor`; scripts that ran `fartcrobat` need the new name.
- **AppImage:** the update replaces the file in place, so it keeps its old file name until you rename it.
- **Remembered passwords** on Mac and Linux may have to be typed once more: the system keychain stores them under the app's name.
- **Claude Desktop and ChatGPT Desktop:** open Inkmoor once after the update before asking an AI app to use it; after that, the installed Claude extension and ChatGPT setup keep working. (On Windows after Later, and on Ubuntu and Debian, the old extension cannot start the app by itself until then.) Add the Claude extension again from **Preferences → AI apps → Add to Claude Desktop** to see the new name.

### For administrators

Machine policies move to `HKLM\SOFTWARE\Policies\Inkmoor` on Windows, `/etc/inkmoor/policy.json` on Linux and `/Library/Application Support/Inkmoor/policy.json` on Mac. Policies at the old Fartcrobat locations still apply; where both set the same setting, the new location wins.

Windows installers remain unsigned; macOS builds are ad-hoc signed.
