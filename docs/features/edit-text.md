# Feature: edit-text

Acrobat 'Edit a PDF' (tool group 'edit', owner of its panel) — editing existing page text and adding new text, as real page content (not annotations).

- Edit panel (ToolPanelFrame 'Edit a PDF'): rows for tools edit.content ('Edit text & images'), edit.addText ('Add text'), edit.addImage, edit.link (from edit-images-links, if registered), marks.crop and the page-marks commands (headers/footers, watermark, background, Bates — if registered), organize.open, ocr.recognize, plus the formatting controls for the selected text block (font, size, colour, bold, italic, underline, alignment, line spacing) — like Acrobat's Edit panel. Default tool when opening the group: edit.content.
- edit.content mode: outlines every text block on visible pages (from doc.pageText blocks/lines; merge lines into paragraphs sensibly) with thin boxes; hovering highlights; click a block -> an in-place editor (contenteditable) positioned over the block at the current zoom, showing the block's text with the original font approximated (map PDF font names/flags to CSS families: serif/sans/mono, bold/italic) and real size/colour, caret where clicked. The page render under the editor hides the original text while editing (draw a page-coloured cover or render with the block's text removed preview). Supports typing, deleting, line breaks, selection, Mod+B/I/U, size/colour/font changes from the panel or a floating mini toolbar; Esc cancels; clicking outside commits.
- IMPORTANT: your tool layer must be `pointer-events: none` except on your text block boxes and your editor, because edit-images-links adds a page layer (when toolId === 'edit.content') with image hit boxes underneath. Use custom selection type 'edit-text:block'.
- Commit (engine namespace 'edit-text', one mutation 'Edit Text'): remove the original glyphs of the block (redaction limited to text: create a Redact annotation over the block's exact line quads and apply with black_boxes false, image method NONE, line-art NONE, text REMOVE — make sure it removes only glyphs whose bbox lies inside, so neighbouring text survives; or rewrite the content stream if you find a more precise way), then write new text as page content: a new content stream appended to /Contents (save/restore graphics state around the original content), BT/ET with Tf/Td/TJ, using (a) the original embedded font when the needed glyphs exist (doc.addFont(font) with the font from the structured-text walker — check encodeCharacter for every character) else (b) a base-14 match (Helvetica/Times/Courier families with bold/italic variants via doc.addSimpleFont(new Font('Helvetica-Bold'))) — wrap lines to the original block width, keep the original line height/alignment, colour as rg. Handle rotated pages (page /Rotate) correctly by working in user space (s.pageToUser).
- edit.addText: click (or drag a width) to create a new text block with the current font settings, then the same editor; commit writes page content.
- Undo/redo must restore the original text exactly (journal). Large docs: only process the edited page.
- Unit tests: replace 'Hello Fartcrobat page 1' with 'Goodbye' on text.pdf page 1 and check doc text, that the next line is untouched, that undo restores, that it survives save/reopen, that rotated pages (mixed-sizes.pdf page 3) work, and font fallback for characters missing in a subset font.
e2e: open text.pdf, open Edit a PDF, click the 'Chapter 1' heading, select all and type 'Introduction', click outside; page text now contains 'Introduction' and not 'Chapter 1'; change the size of a paragraph via the panel; add new text with Add text; undo; screenshots before/after (look at them: the new text must be crisp, at the right place, no overlapping old glyphs).
