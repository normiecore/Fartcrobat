# Feature: forms-fill

Filling interactive PDF forms (AcroForm) like Acrobat Reader/Pro.

- pageLayer 'form-fields' (order 50, mounted when the active tool allows default interactions or is 'select', or fillsign tools): overlays a control on every widget from core forms.list(page) (refetch on page version): text (single/multi-line textarea, password, comb (letter-spaced cells), maxLen, alignment, font size from DA scaled by zoom — use 'auto' sizing when DA size is 0), checkbox and radio (click toggles; keyboard Space), combo box (dropdown with options; editable combos allow typing), list box (single and multi-select), push buttons (reset-form action works; submit/other JS shows a toast that it is not supported offline), signature fields (unsigned: click dispatches 'fartcrobat:sign-field'; signed: show tooltip 'Signed by … — see Signatures panel'). Controls are transparent until focused (the MuPDF appearance shows through); when focused they show the editable value on a white/light-blue background. Commit on blur/Enter/change via forms.setValue (undoable), then the page re-renders with the new appearance. Read-only fields are not editable. Required fields get a red outline. Field highlighting (prefs.highlightFormFields, Acrobat's light blue) toggled from the form bar.
- Tab/Shift+Tab move between fields in tab order (page by page; within a page by /Tabs order if present else row-major), scrolling the next field into view; Enter in single-line text commits and moves on.
- Document message bar (a slim bar at the top of the document area — implement as a global component positioned over .shell-viewer-wrap, or a docToolbar item) when info.hasForm: 'This document contains interactive form fields.' with buttons 'Highlight existing fields' (toggle) and 'Clear form' (forms.reset after confirm). For XFA forms (info.hasXfa) say that dynamic XFA forms are not supported and that static fields are shown.
- Acrobat JavaScript subset (MuPDF's WASM build has no JS): implement a safe interpreter for the scripts in FieldInfo.scripts covering what real forms use: AFNumber_Format/AFNumber_Keystroke (decimals, separator style, negative style, currency symbol and prepend), AFPercent_Format/Keystroke, AFDate_FormatEx/KeystrokeEx/AFDate_Format, AFTime_Format, AFSpecial_Format/Keystroke (zip, zip+4, phone, SSN), AFSpecial_KeystrokeEx masks, AFRange_Validate, AFSimple_Calculate('SUM'|'AVG'|'PRD'|'MIN'|'MAX', [names or 'field.*']), and simple custom calculation scripts of the form `event.value = expr` where expr uses getField('a').value, + - * / parentheses, numbers, Math.round/min/max (parse it yourself — do NOT use eval/new Function). Keystroke validation blocks invalid characters while typing; format shows the formatted text in the field appearance using forms.setValue(id, raw, {display}); calculations run in /CO order (forms.calculationOrder) after any value change and write via forms.setValues in one step; validation failures show Acrobat-like messages ('The value entered does not match the format of the field [ price ]'). Unit-test the interpreter thoroughly.
- Form data: commands forms.exportData / forms.importData (menu 'forms'): XFDF and JSON (and FDF import if feasible), plus forms.reset ('Clear Form'), forms.highlightFields toggle. Preferences section 'Forms': highlight colour toggle, show the form message bar, auto-calculate field values.
- Engine namespace 'forms-fill' only if needed (e.g. tab order /Tabs, export values).
