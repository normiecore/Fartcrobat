# Feature: ocr

Acrobat 'Scan & OCR' (tool group 'ocr') — make scanned pages searchable with an invisible text layer, fully offline.

- Tesseract.js (v7, installed with tesseract.js-core and @tesseract.js-data/eng) must run inside the packaged Electron app without network: import the worker script, core (wasm/js, simd + non-simd variants) and eng.traineddata.gz with Vite '?url' imports from node_modules (relative paths like '../../../node_modules/...' if bare subpaths are blocked by package exports) and pass workerPath/corePath/langPath/gzip to createWorker; set workerBlobURL false. Verify it works in the BUILT app (npm run build + e2e), not just in Node. The renderer CSP allows 'wasm-unsafe-eval', blob: workers and same-origin fetches (app://). If you must change the CSP in src/renderer/index.html, keep it minimal and report it as a core change.
- Recognize text (command ocr.recognize; panel 'Scan & OCR'): options: pages (current/all/range), language (English bundled; mention others need the traineddata file: allow 'Add language…' that copies a user-supplied <lang>.traineddata(.gz) into userData/tessdata via file:write and uses it), output 'Searchable image' (invisible text) and 'Editable text'? (not needed), resolution (300 dpi default), 'Skip pages that already have text'. For each page: render it to PNG at the chosen DPI (doc.core.render.image), run tesseract (word level boxes + confidence), convert pixel boxes to page space, then call an engine mutation (namespace 'ocr') that adds an invisible text layer: a content stream with BT ... 3 Tr ... ET drawing each word with a font that can encode it (Helvetica WinAnsi via addSimpleFont for Latin; for others use a CID font: doc.addFont(new Font('...')) and encode glyphs; or a GlyphLessFont approach), sized/scaled (Tz horizontal scaling) so each word's quad matches the image word box — so text selection, search and copy line up with the visible words. Work in user space with s.pageToUser (rotated pages!). One undo step for the whole OCR run (call the mutation once with all pages, or one per page is acceptable but then label 'Recognize Text (page N)').
- Progress dialog with per-page progress and Cancel (terminate the tesseract worker); reuse one worker across pages; dispose when done.
- Scanned-document detection: on document open (onDocumentOpen), sample up to 3 pages: if they have images covering most of the page and (almost) no text, show a dismissible document message bar 'This document appears to be scanned. Recognize text to make it searchable?' with a button.
- Preferences section 'OCR': default language (prefs.ocrLanguage), DPI, detection prompt on/off.
- Unit tests (Node): the engine op adds invisible text whose extracted words and quads match given boxes (fake OCR result), rotated pages, non-Latin characters; tesseract itself can be tested in Node too (tesseract.js works in Node) on tests/fixtures/scan.png to check the pipeline (recognises 'Scanned Document').
e2e (most important): open scanned.pdf, the scanned-document bar shows, run Recognize text on the page, wait, then Ctrl+F 'searchable' finds 1 hit whose highlight rectangle overlaps the word in the image (screenshot and look), select text with the mouse and copy works.
