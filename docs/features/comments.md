# Feature: comments

Comment interaction layer, popup notes, Comments panel and comment management (the creation tools are built by markup-tools; you make every comment selectable, editable and reviewable).

- pageLayer 'annotations' (order 40, mounted when the active tool has allowDefaultInteractions or is 'select'): lists comments with core annots.list(page) (refetch on usePageVersion), renders invisible hit areas (for text markup use quads, for ink a padded bbox but hit-test strokes with tolerance, for lines the segment), hover outline, click to select (doc.setSelection({kind:'annotations', page, ids})), Shift/Ctrl-click to multi-select, click empty space clears (let events through to the text layer when not over a comment). Selected: blue bounding box with 8 resize handles for rect-based types (Square, Circle, FreeText, Stamp, Ink, Polygon, PolyLine, FileAttachment...), endpoint handles for Line/arrows, no resize for Text notes and text markup. Drag to move (live preview: render the annotation bitmap via doc.core.render.annotation(id, scale) and setHiddenAnnotations while dragging; commit with annots.move/transform), Shift constrains, arrow keys nudge 1pt (Shift = 10pt), Delete removes (command comments.delete shortcut ['Delete','Backspace'] enabled only when selection.kind==='annotations'), Escape deselects, Mod+D? no. Locked annotations cannot move.
- Double-click a FreeText to edit its text inline (textarea overlay matching font size/colour; commit on blur/Ctrl+Enter, Esc cancels). Double-click any other comment opens its popup note.
- Popup notes: Acrobat-style floating note window anchored near the annotation (draggable, resizable): author, date, editable contents (saves on blur, undoable), reply thread with 'Reply' box, status menu (Accepted/Rejected/Cancelled/Completed/None via annots.setState), close. Listen to window 'fartcrobat:edit-annotation' {docId,id,page} to open the popup (Text) or inline editor (FreeText) for freshly created comments. Hovering a comment shows a small tooltip with author and the start of the text.
- Context menu on a comment: Open Pop-up Note, Reply, Set Status ▸, Mark with Checkmark (Marked state), Delete, Properties…, Copy Text, Bring to Front/Send to Back? (optional).
- Properties: a compact floating inspector shown when one comment is selected (above/below it) with colour, fill colour (where applicable), opacity slider, line width, line style (solid/dashed/cloudy), arrow ends for lines, font size and text colour for FreeText, plus 'Properties…' dialog with tabs Appearance / General (Author, Subject) / Review History (states). All edits via annots.update (undoable). 'Make current properties default' stores defaults per type in store ('comments:defaults:<type>') which markup-tools can read (document the key format in your report).
- Right panel 'comments' (order 30): all comments (annots.listAll; refresh on docVersion/page changes) grouped by page; each card shows type icon + colour, author, relative date, contents (editable inline), highlighted text for text markup (look up the text under the quads via doc.pageText), replies (indented, add reply box), status badge, checkmark; click selects the comment and scrolls to it (doc.view.scrollToRect); filter by type / author / status / colour; sort by page, date, author, type; search box; 'Expand all / Collapse all'; count; empty state; selecting a comment on the page highlights the card.
- Commands (menu 'comment'): comments.toggleVisibility ('Show/Hide Comments', toggles doc.state.showAnnotations; also in View > Show/Hide), comments.export (XFDF (default) and FDF; build XFDF XML in the UI from annots.listAll), comments.import (XFDF/FDF; parse with DOMParser in the UI, create annotations via annots.create; support the common XFDF elements: text, highlight, underline, strikeout, squiggly, freetext, square, circle, line, polygon, polyline, ink, stamp), comments.summarize (create a new PDF summarising all comments: for each page a list of comments with author/date/text; open it with openNewDocument — build it in your engine namespace with MuPDF text drawing or as a simple generated PDF), comments.deleteAll (confirm), comments.flatten (Print production > Flatten: annots.flatten after confirm), comments.next/previous (navigate between comments).
- Preferences section 'Commenting': author name (prefs.authorName), show comment popups on hover, open popup when creating notes, default font size for text boxes.
- Engine (namespace 'comments'): anything not in core annots (e.g. reorder/bring to front, summary PDF generation). Unit-test it.
e2e: open text.pdf, create a Square and a sticky note through engine calls in page.evaluate (markup tools are not yours), then via the UI: click the square to select it (bounding box visible), drag it 50px and check rect moved, undo restores, change its colour in the inspector, press Delete removes it; open comments panel, see the note, add a reply in the panel, set status Accepted; export XFDF via stubbing the save dialog (stub invoke('file:saveDialog') to return a temp path) and re-import into a fresh document.
