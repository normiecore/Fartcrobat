# Feature: export-create

Acrobat 'Export a PDF' (tool group 'export') and 'Create a PDF' (tool group 'create'), plus Office/HTML conversion on open.

EXPORT (commands export.word/excel/powerpoint/image/text/html, File > Export To ▸ submenu; panel with format radio list + options + Export button; output via saveBytesAs with the right filter; for images choose a folder):
- Word (.docx, package 'docx'): reconstruct paragraphs from doc.pageText blocks/lines/spans: font family mapping, size, bold/italic, colour, alignment guess (left/centre/right/justified from line positions), line breaks vs paragraph merge, hyphenation joins, headings (larger font → Heading styles), bullet lists (•, -, 1.), simple tables (detect aligned columns across consecutive lines → Word tables), images (extract via an engine op returning PNG/JPEG bytes and size for page images; place inline at their position order), page breaks between pages, page size/margins from the PDF. Option 'Retain flowing text' vs 'Retain page layout' (page layout: absolutely positioned text boxes/frames per block). Must open in Word/LibreOffice: verify by converting the result back with LibreOffice (soffice is installed in this dev container: `soffice --headless --convert-to pdf`) in a unit/integration test and checking the text survives.
- Excel (.xlsx, exceljs): detect tables per page (rows from lines, columns from consistent x gaps), numbers parsed as numbers (currency, %, thousands separators), one worksheet per page or one for all ('Combine pages into one sheet' option).
- PowerPoint (.pptx, pptxgenjs): one slide per page with the page rendered as a background image and editable text boxes for text blocks on top (option: image only).
- Image: PNG or JPEG (quality), DPI 72/150/300/600, pages range, colour/grayscale; one file per page named '<name>_Page_1.png' into a chosen folder; TIFF (multi-page) optional (write an uncompressed/deflate TIFF encoder yourself if you do it).
- Text (.txt, plain text with page breaks \f optional) and HTML (MuPDF stext asHTML per page, combined into one standalone HTML file with embedded images as data URLs if feasible).
- Do heavy work off the UI thread: engine namespace 'export-create' ops to gather structured content (text with fonts + image bytes) and build documents either in the worker (if the libraries work there — test it) or in the UI with progress.
CREATE (tool group 'create', Home tile, works without an open document; commands create.fromFile, create.blank (Letter/A4/custom size, pages), create.fromClipboard (clipboard image via invoke('clipboard:readImage')), create.fromImages (multi-select images -> one PDF, page size = image size at its dpi or fit to Letter/A4 with margins option), create.fromWebPage is NOT available offline but 'From HTML file' is):
- fileConverters (registry) for Office files: main.ts (feature main process) detects LibreOffice: prefs.libreOfficePath, `soffice`/`libreoffice` in PATH, standard install paths on Windows (C:\Program Files\LibreOffice\program\soffice.exe), macOS (/Applications/LibreOffice.app/Contents/MacOS/soffice) and Linux (/usr/bin/soffice, /usr/lib/libreoffice/program/soffice, snap/flatpak); converts with `soffice --headless --norestore --convert-to pdf --outdir <tmpdir> <file>` using a private user profile (-env:UserInstallation=file:///tmp/...) so it works while LibreOffice is open, with a timeout; returns the PDF bytes. Extensions: doc, docx, odt, rtf, xls, xlsx, ods, csv, ppt, pptx, odp, txt? (txt: let MuPDF do it). If LibreOffice is missing, return null so the core falls back to MuPDF's built-in importer (docx/xlsx/pptx) and show a one-time toast 'Install LibreOffice for best Office conversion quality' with the download URL shown as text (https://www.libreoffice.org/download/).
- HTML files (.html/.htm): main-process conversion with a hidden BrowserWindow + webContents.printToPDF (page size Letter/A4, margins, print background) — offline, local files only (block network requests in that window).
- Settings section 'Convert': LibreOffice path (with Browse… and 'Detect' showing the found version via `soffice --version`), default export formats/options.
- Unit/integration tests: docx export of text.pdf contains 'Chapter 1' as a heading and the lorem paragraphs (unzip and inspect word/document.xml; round-trip via soffice to PDF when available), xlsx export of a table fixture you create (tests/fixtures/export-create/table.pdf with a 4×5 table incl. numbers) yields numeric cells, pptx has 5 slides, images export produces PNGs of the right pixel size, LibreOffice conversion of a .docx you generate (python-docx is available) works through the main-process handler logic (unit-test the pure conversion function with Node child_process, skipping when soffice is absent).
e2e: open text.pdf, export to Word (stub file:saveDialog to a temp path) and check the file exists and is a zip with word/document.xml; Create PDF from scan.png + compare-a.pdf via stubbed open dialog -> new tab with 2 pages; open a .docx file through openPaths -> converted tab (LibreOffice path).
